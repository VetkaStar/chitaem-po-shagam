# План развития «Читаем по шагам»

Статус: рабочий редакционный план, не аккредитованная образовательная программа. Для всех детей; приоритет удобства для детей с аутизмом, СДВГ и ЗПР. Возраст — справочная настройка, не основание автоматически закрывать или усложнять задания. Итоговую последовательность и формулировки до релиза нужно проверить с учителем-дефектологом/логопедом и семьями.

## Что уже работает

- Первый вход, локальный профиль, выбор раздела, настройки движения/звука/перерывов.
- Буквы, слоги, слова, картинки. В слогах после каждого второго принятого ответа можно собрать слово из частей.
- 13 тем: А/У/М → О → Х → С → Н → Ы → Л → Р → К → Т → И → П → свободный полный алфавит. Последний пункт — свободная практика, не завершённый курс остальных букв.
- 4 предложения, 3 рассказа и 3 стихотворения. Чтение по строкам и один вопрос на понимание; распознавание произношения длинных текстов здесь пока не применяется.
- Кабинет показывает накопленные звёзды. Герой, костюмы, питомец и синхронизация только анонсированы.

## Опора на учебник и границы использования

Исходник: Аксёнова, Комарова, Шишкова, «Букварь», часть 1. Локальная копия work/bukvar-part1.pdf хранится вне публичного репозитория. Ранее проверялись страницы 40–53; при этом обновлении визуально проверены 54 (Н), 58 (Ы), 61 (повторение), 62 (Л). Использован общий переход «буква → слог → слово → смысл». Тексты страниц и книжные иллюстрации не перенесены. Дальнейшая последовательность Р/К/Т/И/П — собственный предварительный маршрут, а не заявление о точном порядке учебника. Скан не добавлять на сайт и в GitHub.

## Как наполнять курс

Каждая тема должна иметь конкретную цель и 3–5 коротких занятий. Ребёнок выбирает следующий шаг, уровень не блокируется. В одном занятии: короткое повторение знакомого → новый звук/слог → смешанное повторение → слово из знакомых частей → вопрос о значении. Перерыв определяется настройкой, без давления и таймера на ответ.

| Пакет | Что подготовить | Результат |
| --- | --- | --- |
| 1. Первые соединения | А/У/М, О/Х/С; 6–12 контрастных слогов на тему, слова МАМА, МУХА, ОСА | Узнаёт части и соединяет их в слово |
| 2. Н/Ы/Л | НО/НА/НУ, МЫ/НЫ/СЫ, ЛА/ЛУ/ЛЫ; НОС, УСЫ, ЛУНА, СОСНА | Читает слова из доступных букв, замечает изменение одной буквы |
| 3. Р/К/Т/И/П | 6–10 слогов и 6–12 слов на тему, открытые и закрытые слоги | РАМА, РУКА, КОТ, КИТ, ПАПА, ЛАПА; мягкость с И показывать со взрослым |
| 4. Остальные согласные | Отдельные мини-темы Б/В/Г/Д/З/Ж, затем Ш/Ч/Щ/Ц/Ф; порядок проверить | Снять нынешний скачок от П к свободному алфавиту |
| 5. Й, Е/Ё/Я/Ю, Ь/Ъ | Разделить функцию буквы и название звука; короткие пары и примеры | Не объяснять сложное правило только цветом или синтезированной озвучкой |
| 6. Предложения | 20–30 предложений от 2 до 6 слов, кто/что делает/где, сборка из слов | Ребёнок понимает прочитанное, а не только узнаёт карточки |
| 7. Рассказы | 12 бытовых историй по 3–6 предложений, затем порядок событий | Ответ на явный вопрос, позже простой вывод с опорой на текст |
| 8. Стихи | 12 собственных/лицензированных коротких стихов, 2–4 строки сначала | Ритм, смысл, добровольное повторение без требования заучивать |

## Карточка материала: что передавать разработчику

Один UTF-8 JSON или TypeScript-массив на пакет; идентификаторы постоянные. Не встраивать тексты в JSX. Для каждой единицы:

```json
{
  "id": "word-luna-01",
  "kind": "word",
  "unitId": "letter-l",
  "target": "ЛУНА",
  "parts": ["ЛУ", "НА"],
  "requiredLetters": ["Л", "У", "Н", "А"],
  "meaning": "Её видно в ночном небе.",
  "imageId": "luna-main",
  "alternateImageId": "luna-sky",
  "acceptedNames": ["МЕСЯЦ"],
  "visibleParts": ["КРАТЕР"],
  "visualConfusions": ["СЫР", "БАНАН"],
  "hint1": "Посмотри на небо вокруг.",
  "hint2": "Первый слог — ЛУ.",
  "helpText": "ЛУ и НА вместе — ЛУНА.",
  "source": "author-original",
  "reviewStatus": "draft"
}
```

Это целевая схема следующего расширения, не уже реализованный импорт произвольного JSON. Сейчас точки подключения: lib/learning.ts (темы), content/word-bridges.ts (части/значение), content/reading-library.ts (тексты и вопросы), lib/session.ts (варианты названий/части/сходства). Новые изображения подключать через реестр с постоянными imageId; не вставлять путь в каждый компонент. Обработчик будущего импорта должен проверять схему до сохранения и показывать список ошибок.

Для рассказа/стиха нужны id, kind, title, lines, question, options, answer, hint. Пример точной рабочей схемы находится в content/reading-library.ts. Правильный ответ должен присутствовать среди вариантов ровно один раз. Каждый текст должен иметь минимум 2 дополнительных вопроса в редакционном пакете; интерфейс впоследствии будет выбирать один случайно.

## Обратная связь

1. Верно — подтвердить, показать слово целиком, начислить звезду один раз за попытку.
2. Подходящее другое название — «Да, котик тоже подходит. Здесь потренируем короткое слово КОТ».
3. Названа видимая часть — подтвердить наблюдение и спросить о целом, не помечать как ошибку знания.
4. Визуальная неоднозначность — признать сходство и показать альтернативную картинку с контекстом.
5. Опечатка — выделить конкретные буквы; не говорить, что ребёнок не узнал предмет.
6. Неясная речь — не засчитывать неверный ответ; показать, что попытка услышана, дать время.
7. Повторные затруднения — часть слова → пример → совместное чтение → доступный отдых. Без потери звёзд.

## Вариативность

Перемешивать карточки и позиции ответов, не повторять одну карточку подряд; менять рисунки и вопросы, но сохранять учебную цель. Не добавлять непроверенные буквы в задания начального чтения. У свободной практики слов сейчас отдельный расширенный словарь: позже разделить «только изученные буквы» и «любые первые слова» настройкой. Для историй менять текст целиком или вопрос, не перемешивать предложения связного рассказа автоматически. Перестановку событий оформлять отдельным заданием.

## Картинки и звук

Подробный список: IMAGE-BRIEF.csv. Приоритет P0 — убрать неоднозначные эмодзи основных 12 картинок. P1 — значения первых слов и 6 сюжетных сцен. На каждый предмет нужны основной и альтернативный ракурс; смысл должен совпадать. Для луны обязательный контекст ночного неба; для банана — отдельный целый плод и вариант с кожурой. Не копировать иллюстрации букваря.

Изображения: WebP/PNG, 1024×1024, рабочий предмет в центре, поля 12%, спокойный фон, без текста/логотипов, хорошая различимость на телефоне. Сюжеты: 1600×900, один главный эпизод. Передать файл, alt, список всех видимых предметов/деталей, допустимые ответы, права/автора. Персонаж/одежда/питомец — отдельный будущий пакет; не смешивать декор с изображениями учебных предметов.

Озвучка: отдельные проверенные записи звуков, слогов и слов. Синтез речи может озвучивать название буквы вместо звука; для обучения слиянию нужен контроль специалиста. Все записи с ясной лицензией/согласием диктора, без записей детского голоса. Автовоспроизведение только по настройке.

## Приёмка каждого пакета

Проверить буквы относительно этапа, сборку parts.join('') == target, уникальность id, правильный ответ, доступность файлов, варианты названий/опечаток. Проверить мышь, клавиатуру, сенсорный экран, увеличение текста, отсутствие автоозвучки в ручном режиме, паузу микрофона при смене экрана. Затем пробное занятие с семьями и фиксация трудностей без имён/диагнозов. Публиковать только проверенный пакет; статус draft не превращать автоматически в обязательный учебный маршрут.

## Следующие технические этапы

1. Реестр контента с устойчивыми id и валидатором; отдельные данные для тем вместо индексов.
2. Вопросы из пула, сборка предложения, упорядочивание событий, история пройденных текстов.
3. Локальные несколько профилей и экспорт/импорт сохранений с понятным выбором замены/объединения.
4. Настоящий аккаунт и синхронизация — отдельная серверная задача с правилами детских данных; не имитировать вход.
5. Кастомизация: инвентарь, подтверждение покупки за звёзды, защита от повторного списания, возможность сменить наряд. Никаких денежных покупок для ребёнка.
