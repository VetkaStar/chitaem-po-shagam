# Демонстрационные эпизоды — этап 3

14.09.2026. Обе демонстрации реализованы и пройдены через общий экран занятия в изолированном браузере. Основной AppPortal пока не подключён; публикации нет.

## Авторский порядок

| Демонстрация | Последовательность |
| --- | --- |
| P1 — ep.p1.C01.91, 5 экранов | ЛУ и ПА → модель ЛУПА → сборка → чтение целого → значение |
| P2 — ep.p2.P05.91, 6 экранов | Значение ЛУНА → чтение → выделение ЛУ → преобразование → чтение ЛУПА → значение |

Это знакомство с двумя способами, не сравнительный диагностический тест. Впечатление «Было удобно», «Нужна помощь» или «Пока не знаю» сохраняется только по явному выбору. Успешные ответы не выбирают метод автоматически и не подтверждают освоение курса.

## Архитектура и сохранение

- lib/curriculum/demonstrations.ts выбирает только авторские эпизоды methodComparison.
- features/curriculum/demonstration.ts планирует, запускает и завершает их шаги. Применяются те же исполнители, что для курса.
- Единственный CurriculumController владеет очередью и commit. Отдельного хранилища или второго профиля нет.
- ProgressState v2 расширен необязательным demonstrationRuns. Для P1/P2 отдельно сохраняются позиция, активный информационный planId, отложенный экземпляр и впечатление. Старые состояния без этого поля принимаются.
- Источник demonstration отделён от recommended/custom/free. Задания используют исходные context=demo, phase=demo, programId=null, nodeId=null и точные episodeId/stepId.
- Ответ оценивает engine.recordAttempt без согласования официального маршрута. Позиции курсов, отложенные задания и информационные экраны сохраняются.
- Журнал demonstration_step связывает каждый завершённый шаг с ответом либо подтверждённым информационным показом. Импорт проверяет точный порядок, источник, план и экземпляр; нельзя просто заменить позицию на конец.
- Экспозиции общие: увиденное/услышанное в демонстрации влияет на свежесть будущих проверок. Помощь сохраняется до раскрытия.
- Каждый новый экран расходует бюджет. Перезагрузка и переключение методов восстанавливают текущий экран без повторного расхода.

Дополнительные стили не создавались: используются классы из app/globals.css. Исходная поставка и контрольные суммы сохранены.
