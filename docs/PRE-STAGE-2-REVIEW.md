## Подтверждённая ошибка

### P2 — несогласованный импорт пропускает шаг самостоятельной дорожки

Место: lib/progress/validation.ts:185 — шаги custom и сохранённые экземпляры проверяются отдельно; features/curriculum/controller.ts:153 — позиция увеличивается после завершения экземпляра.

Воспроизведено двумя проверками одного сценария: дорожка содержит МА, экземпляр уже предъявлен. В экспортированном JSON меняется только steps[0].itemId на МУ. Импорт принимается. Ответ на сохранённое МА увеличивает position до 1, следующий план возвращает custom_complete; МУ не предъявлялось.

Фактические ID: task.41a973db156b → task.399717abd1f9. Скрипт воспроизведения: .local/review-controller.mjs, запуск локальным .local/node/bin/node.exe. Это проверка будущей поддержки custom, не ошибка старых свободных тренажёров.

Исправление: связывать активный и отложенный экземпляры с источником, routeId/version и текущим steps[position], проверять itemId/mode. При несовпадении импорт должен завершаться отказом без изменения сохранения. Добавить регрессии для активного и отложенного экземпляра.

## Несоответствие принятому правилу стилей

Сейчас в app/components/features найдено 22 CSS-файла. app/globals.css — главная точка общих стилей, но не единственное место их хранения. ReadingApp.tsx:2 и последующие импорты подключают отдельные lesson CSS; собственные импорты есть у компонентов, портала и библиотеки. Моё прежнее предложение ограничиться добавлением новых стилей в globals.css не устраняло это расхождение.

AST-проверкой найдены 11 style-атрибутов непосредственно на DOM-элементах TSX. Дополнительно style передаётся портальным диалогам ParentSettings/RestDialog. AppPortal.tsx:72 напрямую меняет CSS-переменную масштаба, lib/vision.ts:32 создаёт объект оформления. Prop style у Welcome — данные выбора оформления, он не посчитан как DOM inline-стиль.

Часть значений динамическая: скорость и пауза карточек, размеры сеток, палитры, длина записи, высота индикатора звука. Их нельзя просто удалить. При приведении к правилу пользователя состояния остаются в логике, правила отображения переносятся в globals.css и связываются через классы/атрибуты. Дополнительный CSS-файл не нужен.

Объединять нужно с сохранением действующего каскада, слоёв Tailwind, путей шрифтов и приоритетов оформления. Простая склейка файлов по алфавиту не является проверенной миграцией. Перед изменением требуется зафиксировать вид и вычисленные стили существующих экранов; после — сравнить их.
