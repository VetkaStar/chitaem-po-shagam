## Ограничения перед широким выпуском

1. **Реальная детская речь.** Дефект 003 из `BUGS-AND-FIXES.md` не закрыт: нужны записи правильного, неполного и неверного чтения на целевых устройствах, чтобы отделить ошибку распознавателя от ошибки зачёта. Порог автоматически не снижен.
2. **Приёмка визуального результата и доступности.** Проверены адаптивность и конкретные сценарии клавиатуры, но полный проход со скринридером, реальный мобильный Safari/Android и попиксельное соответствие всему комплекту макетов не выполнены.
3. **Граница первой версии.** Магазин, персонаж/питомец и синхронизация обозначены в интерфейсе как будущие возможности. Они не реализованы и не включаются в перечень работающих функций. Наполнение ранних тем и плавное введение оставшихся 19 букв также требуют учебного решения: обзор алфавита теперь обозначен явно, новые темы не добавлялись.

Технический долг: два адаптера пока используют ScriptProcessorNode; 10 предупреждений сохранены как предупреждения, не замаскированы исправлением. Настройки линтера приведены к фактическому сборщику, неизменяемое стороннее учебное ядро исключено из lint и проверяется собственными тестами/контрольными суммами.

## Повтор проверки

Из корня проекта с Node и менеджером пакетов в PATH:

```text
npm test
npm run typecheck
npm run lint
npm run test:styles
npm run test:browser
npm run test:layout
npm run build
npm run test:production
```

Для Windows здесь используется `.local/node/bin/node.exe`, локальный pnpm и внешний Playwright через `PLAYWRIGHT_PACKAGE`. Браузерные проверки создают изолированные тестовые профили. Реальные модели проверяются отдельно `tests/piper-browser.mjs` и `tests/speech-models-browser.mjs`; последний требует локальной `.local/speech-tests/sample.wav`.

В CI добавлены lint и контроль стилей к существующим unit/typecheck/build. Browser suite в CI автоматически не включена: Playwright не является зависимостью поставки. Публикация выполняется координатором явным HTTPS refspec `HEAD:refs/heads/new-design`, без force и переключения рабочей ветки. После deploy необходим отдельный production-прогон на фактическом Pages URL; его результат сохраняется в `.local/published-browser/`.
